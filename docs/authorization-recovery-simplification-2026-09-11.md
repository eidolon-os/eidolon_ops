# 授权恢复与 generation 简化实施方案

Owner 与逻辑 Host 一一对应；Mobile 可以保存多个独立 Host。物理换板有两种含义：完整恢复原 Host，或者建立新 Host。普通部署、换手机和撤销单个配对都不重建 Owner。

## 产品规则

| 操作 | 结果 |
| --- | --- |
| 更新和重启 | 保留身份、授权与用户数据 |
| 完整备份恢复/迁移 | 恢复备份时的同一 Host/Owner；保留配对；旧实例退出使用 |
| 授权状态缺失、损坏或不一致 | 拒绝不能验证的访问，保留故障现场；不能自动创建空库或开放认领 |
| 明确清空全部授权数据 | 创建新 Host/Owner，用户重新配对；不能复用原身份增加世代 |
| 换手机、撤销控制者或设备 | 使用既有逐项授权/撤销流程；不改变全局身份 |

完整恢复包含身份、凭据、授权/撤销记录、配置和业务状态，并要求一致的快照。已有 `backup` 与 `authority-backup` 是局部备份，不宣称它们是整机迁移。旧快照可能恢复快照之后已撤销的权限；本批不增加独立云端撤销账本，也不承诺快照之外的历史能自动恢复。

## 实施边界

1. 删除 Ops 的世代递增及仅清空 Hub 的 authority-reset 路径；Pi 和 Mac 共用“首次初始化、原样延续、需要恢复”判定。
2. 严格区分全新空目录和已有身份下的状态丢失。数据库缺少标记、孤立 anchor、已消费 bootstrap 都不能作为首次初始化。
3. 显式全量重置准备全新身份与凭据，沿用已有输入生成器和清盘流程。准备失败不得清盘。新 Host 与 Owner 都变化；历史私密输入留在受保护的退役目录，便于操作失败后人工恢复，不冒充整机备份。
4. 已有协议、签名描述和备份中的 generation 原样保留，继续验证历史数据。新身份从协议初始值开始，不再生成新世代。不要修改旧描述或批量清除 Mobile/ESP 保存的信任来隐藏兼容问题。
5. 备份/恢复的范围在 CLI 和文档中明示；完整系统迁移需要单独的、经真实恢复验证的快照，不能将局部恢复改名包装成完整恢复。

## 验收

- 意外丢失授权库或 anchor 时拒绝，身份/凭据/目录内容不变。
- 首次安装和失败重试继续可用；有状态的普通部署保留既有 generation 8/9 等历史值。
- 显式重置产生不同 Host ID、Owner ID；准备失败不删除旧状态。
- 恢复旧格式包继续保留其身份，不签发下一代；损坏/部分包提前拒绝。
- Controller reset 和逐设备撤销保持既有含义，不与整机重置混淆。
- 不在当前 Pi 上执行清盘或重置；真机只验证只读预检和普通更新兼容性。破坏性场景在隔离测试目录验证。

本方案不引入新账号平台、OAuth 服务、Matter 实现或新备份加密算法。完整迁移/恢复验收与本次授权生命周期代码改造分开报告。
